## 1. Production Binary Invariance + Test-Only Resource Witness Architecture

Production binary source files under `extensions/rapidflow_apx/` and `tests/native/rapidflow_apx_engines/src/harness_runner.cpp` are **unchanged** in R2.1 (`NATIVE_SOURCE_COMMIT = 115ce2844d91f6a6588fe0ac50b1179bc3b38012`, binary SHA-256 `3fa35111acd7e7527a80bae6b0caa6d51d1e283d9848747a62c2517d696d1876`).

To exercise genuine C++ `std::bad_alloc` inside active step transactions without mutating production code, R2.1 introduces a dedicated **test-only** executable target `rapidflow_apx_r21_resource_witness` (`tests/native/rapidflow_apx_engines/src/r21_resource_witness.cpp`, SHA-256 `fcdd9c5efd97bf59604d4d3204db03e28bb93f0b42488aa02d252b0a4aa8c7a9`):

- **Mechanism:** Overrides `::operator new` / `::operator new[]` (both throwing and `std::nothrow_t` forms) backed by an atomic allocation countdown armed cleanly via `ScopedOomAfter` and the existing `BoundaryObserverFn` (`MeasurementStage::STEP_EXECUTE_START` / `STEP_EXECUTE_END`) hook in `harness_runner`.
- **Direct Code Paths Witnessed (`--verify-paths`):**
  - `B-W01`: `ApxStreamingEngine::execute_step` `INSERT` path encounters genuine `std::bad_alloc` inside step execution (`tx_manager_` transaction scope) -> `StepStatus::RESOURCE_EXHAUSTED` (and pre-tx `ERROR` when capture setup fails prior to transaction entry), zero graph/codec drift.
  - `B-W02`: M2 traversal/matching callback `std::bad_alloc` inside active `SearchTimingGuard` -> unwind closes `search_ns` / `search_core_ns` (`search_ns >= search_core_ns`), rolls back graph state cleanly, sets `StepStatus::RESOURCE_EXHAUSTED`, and preserves exact rollback invariants.
  - `B-W03a`: `DELETE` transaction under `NlfMode::RESIDUAL` encounters `std::bad_alloc` during search/NLF-enabled execution (`work_units > 0`) with clean rollback.
  - `B-W03b` (**post-callback DELETE graph mutation boundary**): `ApxTransactionManager::execute_update(DELETE)` with `nlf_index_ = nullptr` executes `m2.search_event` on `G_before` confirming edge existence (`callback_reached = true`, `callback_completed = true`), arms `g_oom_countdown = 1` immediately before callback return (`allocation_armed_after_search = true`), bypasses NLF prepare cleanly, and triggers `std::bad_alloc` at `ApxAuthoritativeGraph::apply_delete() -> tombstones_.insert(key)`. All seven read APIs (`has_edge`, `get_edge_label`, `get_degree`, `get_edges_count`, `get_neighbors`, `get_neighbors_into`, `get_neighbors_merged_into`), overlay/tombstone membership, codec, and tuple sink verify exact rollback, and a follow-up `DELETE` with injection disabled (`positive_control_status = SUCCESS`) deletes the edge cleanly.
  - `B-W04`: `execute_update` encounters `std::bad_alloc` after tuple emission has begun (`raw_emissions > 0 || discarded_emissions > 0`); `ApxTupleSink::abort_step` discards pending tuples with zero leaked committed emissions and full graph rollback (precise site within tuple emission vs staging vector growth is not narrowed further).
